## 一、发帖前必读（V2EX 调性红线）

V2EX 用户极度反感硬广，「分享创造」节点尤其看重**真诚 + 干货**。守住这几条，帖子才活得下来：

1. **标题别吹**——不用「最强」「最全」「重磅」，用自述式。V2EX 用户看到夸张词会直接踩。
2. **正文 80% 是数据和发现，20% 是站点**——先给价值，链接放最后一段，一句话带过。
3. **别放一堆链接**——正文只留 1 个站点链接（放结尾）。中途插链接像广告。
4. **回复要快且真诚**——发帖后 2 小时内逐条回评，作者回评是 V2EX 顶帖的核心信号。被质疑就老实承认（比如「数据是从 1c7 仓库同步的，可能有滞后」），别嘴硬。
5. **新号首帖别指望爆**——V2EX 有账号权重，新号首帖可能沉。重点是**不被删、拿到前几个回复**，就算成功。

## 二、主帖文案（直接复制粘贴）

### 标题

```
我把 3000 多个中国独立开发者的产品刷了一遍，有几件事挺意外
```

### 正文

```
去年开始，我把 1c7 那份「中国独立开发者项目列表」做成了一个能搜能逛的导航站（indiemaker.cn），顺手把里面 3000 多个产品全过了一遍。有几个发现，比预想的有意思，分享给同样在做独立开发的你。

1. AI 工具是绝对主力，952 个

分类里 AI 工具最多，952 个，比第二名开发工具（575）多出一大截。图片工具 528、免费工具 524、音视频 495，也大多套了层 AI。

独立开发者的主赛道已经很明确了。现在的问题不是「要不要做 AI」，是「还能做 AI 的哪个细分」。

2. 14.4% 的产品已经停更了

3076 个里，有 442 个标成「已停更」或「开发中」，差不多 14%。这数字比我想象的高。

做独立开发，大多数产品活不过一两年，这是真的。剩下标「已上线」的，有多少真在运营、真有人用，就不好说了。

3. 1829 个开发者，人均 1.68 个产品

最多的一个人挂了 20 多个。独立开发不是「憋一个大招等爆」，是「批量试错、小步快跑」——做得多的，活下来的才多。这个规律从数据里看得特别清楚。

4. 城市分布：深圳压过北京

按开发者所在城市排，深圳、北京、上海、杭州、广州排前五，一共覆盖 142 个城市。深圳这个「搞钱之城」，独立开发者密度反而最高。有点意外，又有点合理。

---

我把这些都整理成了导航站：能搜、能按分类逛、能看每个产品的状态（已上线 / 开发中 / 已停更），数据每天自动同步。

做独立开发的，没事可以去逛逛——看看同行在做什么，也看看哪些方向已经挤满了人。

地址：https://indiemaker.cn

（数据从 1c7 仓库同步，可能有滞后，欢迎指正）
```

## 三、发帖步骤

1. 登录 V2EX → 顶部切到 **「分享创造」** 节点（不是「程序员」节点，别发错）
2. 标题粘贴「二、主帖文案」的标题
3. 正文粘贴全文（V2EX 正文支持纯文本，直接贴，不用 Markdown 语法，`1.` 会自己识别成有序列表）
4. 发布后**立刻自己检查**：帖子能正常打开、链接可点、排版没乱
5. **守 2 小时**逐条回评

## 五、被质疑时的应答话术（备用）

- **「数据准吗？」** → 「数据从 1c7 的 GitHub 仓库每日自动同步，可能有几小时滞后。有错漏欢迎在仓库提 issue。」
- **「这不就是搬运吗？」** → 「对，核心数据来自 1c7 的开源仓库，我做的是把它做成能搜能逛、能看产品状态的导航站，加了分类、状态核验和英文版。」
- **「为什么我的产品没收录？」** → 「可以在 GitHub 仓库提 issue，或者告诉我产品名，我核对后补上。」
