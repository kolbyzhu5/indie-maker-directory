## 三、噪音源已定位，而且是**最后一波**

### 现象
Pages Top10 里 **6 条是 `/indie-maker-directory-<hash>/…` 形式的部署预览路径**：

```
/indie-maker-directory-dplznp8t0f4i/en/topic/pdf.html        4 人
/indie-maker-directory-dplznp8t0f4i/best-ai-tools.html       2 人
/indie-maker-directory-dplznp8t0f4i/local-first.html         2 人
/indie-maker-directory-dplznp8t0f4i/en/local-first.html      2 人
/indie-maker-directory-dplznp8t0f4i/c/ai-tools/6.html        1 人
/indie-maker-directory-dpwhg7180s9n/p/mkdirs.html            1 人
─────────────────────────────────────────────────────
合计 12 位访客 = 总访客的 14.5%（Top10 列表内占 30%）
```

### 为什么加了守卫还有？（实测确认，不是守卫失效）

| 检查 | 结果 |
|---|---|
| 这 6 条路径现在访问 | **全部 404** |
| `.edgeone.cool` 形态裸访问 | **401**（需 token） |
| 今天新部署的产物是否带守卫 | ✅ 带（`dist/index.html` 守卫=1、静态追踪标签=0） |
| robots.txt 是否仍屏蔽 | ✅ 11 组 Disallow |

**原因**：守卫是 9/20 21:30 才上线的。**那些预览部署是在守卫之前生成的，文件里没有守卫** ——
所以它们在被访问时照样上报。（EdgeOne 每次部署生成一份独立的文件副本，守卫只保护「它之后生成的部署」。）

**结论：守住的是未来。这 12 人是历史残留，从今天起新部署都带守卫。**

### 附带发现：预览 token 被打印在公开 CI 日志里 🔴

排查过程中发现的真问题：

- 你的 GitHub 仓库是 **PUBLIC**
- CI 日志里**每次部署都打印带 token 的预览地址**，原文如下（今天的运行）：

```
Deploy URL: https://indie-maker-directory-ogrppciv.edgeone.cool
            ?eo_token=576399f6e78996d02b3da3b8b4120af5&eo_time=1789949889
```

- 实测该 token **当前已过期**（返回 401），所以此刻不可被利用
- 但**每次部署都会生成新 token 并公开**，任何人都能拿它访问预览站
- 影响面：预览站内容与主站相同，泄露的信息有限；但预览站**没有守卫保护之前**会成为统计噪音源与抓取预算浪费

**修法**：CI 里把部署输出脱敏后再打印（保留诊断信息，抹掉 token 与预览域名），约 1 分钟。

> ⚠️ **但本轮建议先不要改**：任何 push 都会触发一次新部署，重新引入预览 URL 与测试流量，
> **污染你正要观察的干净窗口**。等下一个自然部署周期或你说了再动。
