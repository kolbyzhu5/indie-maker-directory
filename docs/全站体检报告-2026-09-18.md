## 二、发现并修复的缺陷

### 🔴 缺陷 1：上游数据里的 Markdown 语法被原样渲染（88 个产品）

**现象**：页面上直接显示原始 Markdown 语法，例如

```
SoulCut —— …支持多机位渲染与音视频同轨编辑 - [GitHub 仓库](https://github.com/0xhappyboy/SoulCut)
mcpp   —— …推动 C++ 进入 `import std` 时代
OmniScope-rs —— …可**有效辅助**开发者定位 FFI 潜在 bug
```

**范围**（扫描全部 2934 个产品）

| 字段 | 污染形态 | 数量 |
|---|---|---|
| description | Markdown 链接 `[文字](url)` | 63 |
| description | 行内反引号 `` `代码` `` | 17 |
| description | 双星号加粗 `**文字**` | 8 |
| maker | Markdown 链接 / 加粗 | 6 |
| **合计受影响产品** | | **88** |

其中 55 个属于「AI 工具 / 免费工具 / 效率工具 / 开发工具」大类，会被首页、榜单页、场景页大量展示。

**影响**：不只是难看——`<meta name="description">` 与 `og:description` 用的是同一字段，**搜索结果里的站点摘要也带着这堆语法残骸**。

**修法**：新增 `cleanText()`，只做「Markdown 语法 → 纯文本」的降级还原（**不改原意**，翻译/改写仍属禁止）：

```
[GitHub 仓库](https://xxx)  →  GitHub 仓库
**有效辅助**                →  有效辅助
`import std`                →  import std
```

清洗加在**两个数据入口**（缺一不可）：
- `scripts/build.mjs` 数据加载处 → 覆盖所有静态模板（详情页 / 分类页 / 榜单页 / 场景页 / sitemap）
- `app.js` 数据加载后 → 覆盖 JS 运行时渲染的卡片

**验证**：线上 8 类页面残骸归零；首页 48 张卡片在「默认态 + 筛选态」下均无残骸。

### 🔴 缺陷 2：外链 URL 混入 Markdown → 生成坏链（2 处，已上线）

**现象**：详情页的「Github」按钮指向一个非法地址，点击跳错页。

```html
<!-- 实际产出 -->
<a href="https://github.com/[WebClocks](https://github.com/WebClocks)">Github</a>
```

**根因**：上游把 Markdown 链接写进了 `makerLinks[].url` 字段（url 里包了个 url）。

**修法**：新增 `cleanUrl()` —— 抓出串内所有 http 片段，取**最后一个**有效值（Markdown 括号里的才是真 URL）；清洗后仍非法的链接直接丢弃。

| 产品 | 修前 | 修后 |
|---|---|---|
| Online Web Clock | `https://github.com/[WebClocks](…)` | `https://github.com/WebClocks` ✅ |
| 在线工具箱 | `https://[github.com/Amd794](…)` | `https://github.com/Amd794` ✅ |

### 🟠 缺陷 3：404 页是云厂商默认页

**现象**：访问不存在的路径，返回的是 EdgeOne 默认页——`title: "Tencent Edgeone"`、无 h1、**无任何站内导航或返回入口**。用户一旦误入就是死胡同，直接流失。

**修法**：新增 `render404Page()` 生成 `404.html`。EdgeOne Pages 约定用**输出目录根部的 `404.html`** 作为 404 响应页（已实测生效）。

新 404 页内容：
- 7 个入口按钮（逛全部产品 / 不上传工具 / 数据报告 / PDF 工具 / 翻译工具 / AI 工具精选 / 独立游戏）
- 8 个热门分类（带产品数）
- 6 条最新收录产品
- `noindex, follow`、不进 sitemap（404 页不该被索引）
- 移动端单列、按钮高 44px（符合触控最小尺寸）

**线上验证**：`404` 状态码 ✓、自有标题 ✓、23 条站内链接全部 200 ✓、移动端无横向滚动 ✓

### 🟡 顺带修复 4：陈旧孤儿页永久残留（本地卫生）

**现象**：`p/` 有 2940 个文件，但产品只有 2934 个 → 残留 5 个陈旧详情页：

| 文件 | 最后生成 | 内容 |
|---|---|---|
| `p/video-watermark-remover.html` | 09-07 | Video watermark remover |
| `p/markdown.html` | 09-11 | 在线Markdown转图片 |
| `p/pro.html` | 09-11 | 软著 Pro |
| `p/project-58a384.html` | 09-11 | 中国独立开发者项目列表（网页版) |
| `p/teamorouter.html` | 09-11 | TeamoRouter |

原因：`p/`、`c/` 只做**覆盖写**，产品改名或下架后旧 slug 的页面不会被删除。

**⚠️ 重要说明：这 5 个页面上线状态是 404，不是线上事故。** 因为 `p/ c/ dist/` 都在 `.gitignore` 里，CI 是全新检出构建，不会带旧文件。但本地会污染排查（我这次就被它误导过——一度以为存在「第二份数据副本」），本地直接部署还会误传上去。

**修法**：生成前清空 `p/ c/`，同步前清空 `dist/p dist/c`。

### 🟡 顺带修复 5：ItemList 结构化数据指向外站（SEO）

首页客户端注入的 `ItemList`，每个条目的 `url` 用的是**产品官网**而不是本站详情页。

目录站的「条目」就是本站的收录页——指向外站既不符合 Schema.org 语义（`ListItem.url` 应是描述该条目的页面），也把权重让了出去。

**修法**：改用 `state.slugMap` 映射到 `/p/xxx.html`。**验证：10/10 条已指向站内。**

## 四、体检方法（三层，缺一不可）

这次体检的最大收获是方法论：**只做渲染层会漏掉一半问题，只做前两层会漏掉「看着对但其实错了」的问题。**

| 层 | 负责什么 | 本次产出 |
|---|---|---|
| **渲染层** | 看得见的问题（横滚/越界/文本溢出/字号） | 全绿 |
| **交互层** | 用得着的问题（点击/输入/切换是否真的生效） | 全绿 |
| **内容层** | 看着对但其实错了的问题（脏数据、坏链、默认 404、陈旧产物） | **抓到 5 个缺陷** |

内容层的判断依据很朴素——**把「数据里有什么」和「页面上显示什么」摆在一起比对**。脏数据不会报错、不会破版、点击也算"成功"，只有主动比对才能发现。

已把这套方法（含可复用脚本）沉淀进 `~/.workbuddy/skills/web-qa-scan/`，新增 `references/scan-content.js`。
