## 二、提交前必须先定的一件事：用哪个 URL

我们站点同时有中文版 `/` 和英文版 `/en/`。**它们共用同一张分享图是不行的** —— 已核实：`og.png` 是纯中文，英文目录站抓到的卡片会是一张老外看不懂的图。

**规则：**

| 提交到 | URL 用 | 分享图 |
|---|---|---|
| 英文站（Uneed / DevHunt / FutureTools / TopAI.tools） | `https://indiemaker.cn/en/` | `og-en.png`（**已生成**） |
| 中文站（AIBase） | `https://indiemaker.cn/` | `og.png`（现有中文图，正确） |

已核实的依据：`/en/` 页面自带的 OG 就是干净的英文，且数字是最新的 ——

> A directory of AI tools, websites, apps and games created by Chinese indie developers. **3,034 products**, updated daily from an open-source repository. No membership, no paid ranking, entirely free.

（顺带发现：中文首页 description 里写的是过期的「2900+」，实际已 3,034。不影响发外链，记在待修项里。）

**为什么敢把外链指向 `/en/` 而不是首页**：站点的 hreflang 是中英双向声明的，Google 会把 `/` 与 `/en/` 当成同一实体的两个语言版本，权重在站点层面归并 —— 不存在"权重被分走"的问题。而 `/en/` 恰恰是当前内链最薄、最缺外部权重的那一页（首页只引 `/c/` 12 条、`/p/` 0 条），外链给它正好补短板。加上英文用户点进来能读懂，这件事没有反方向风险。

**英文分享图已做好**：`og-en.png`（1200×630，与中文版同款版式、同套配色 #b3292e / #f5f0e6）。源文件 `docs/assets/og-en.svg`。
✅ **已上线**（2026-10-03，CI run `37112176019` 全绿）：`en-pages.mjs` 的 og:image 已指向 `/og-en.png`，文件已加入 `build.mjs` 的 dist 同步列表，`copyFile` 的静默跳过改为显式 warn。线上实测 `og-en.png` **200 / 42,915B / 1200×630**、md5 与本地逐字节一致；英文页 **11/11** 指向新图、中文页 12 张仍为 `og.png`（零误伤）。
⚠️ 若某目录站抓到的仍是中文图，那是**它自己侧的图缓存**，在站内编辑页手动替换即可，与本仓库无关。

### 🎁 遇到 `Deals`（Tagline 下方那个区块）怎么办 —— 留空，点 Cancel

界面文案 *"Deals — Offer some special discounts to Uneed's users!"*，展开后要两个字段：`Your deal description`（示例 `30% on the monthly plan`）、`Your discount code`（示例 `UNEED30`）。

**处理：`Cancel`，留空。** 三条依据：

1. **我们没有可打折的东西。** Deal 的机制是「你给折扣码 → 平台给你曝光」，而 indiemaker.cn 是 100% 免费、无会员、无付费排名 —— **这个交易结构上不成立**（不是"不想给"，是"没有这个商品"）。
2. **编一个假折扣码是明确红线。** 用户拿着无效的码回来 → 最轻是差评与举报，最重是账号封停。**虚假信息直接损害平台的信任基础，代价远大于那点额外曝光。**
3. **它是可选项。** 界面上必填字段都带 `*`（Name\* / Slug\* / Url\* / Category\* / Pricing\* / Tags\* / Tagline\* / Rich Description\*），而 **`Deals` 不带 `*`** → 留空不影响提交与审核。

⚠️ **别被输入框里的 `UNEED30` 带跑** —— 那是 **placeholder 示例文本**，不是平台在建议你填什么。

**通用规则（下次投别的目录站同样适用）**：
- 免费产品遇到 `Deals` / `Sell` 这类"发优惠"区块 → **一律跳过**，不要为了拿曝光去编。
- 只有**真存在付费计划**的产品才该填 Deal，且折扣码必须**真能兑换**。
- 判"是不是必填"只看界面上的 `*` 标记，不靠猜。

**🔴 顺带发现的线上缺陷：中文版首页 header 的印章是崩的**

为核对"英文版网站的 logo 长什么样"，用 Playwright 把中英文版 header 各截了一张（`output/uneed-media/hdr-zh.png` / `hdr-en.png`，3× DPR）。结果是：

- **英文版正常** —— 红方块内清晰显示书法体「独立」
- **中文版崩坏** —— 方块内被塞进「AI 独立制造所」6 个字，**文字溢出方块外并被裁切**，第一屏最显眼的品牌位是坏掉的

**根因**：`index.html` 里两个元素**共用了同一个 i18n key**：

```html
<span class="brand-seal" data-i18n="brandTitle">独立</span>       <!-- ← 印章不该被翻译 -->
<span><strong data-i18n="brandTitle">AI 独立制造所</strong><small ...>...</small></span>
```

`i18n.js` 中 `brandTitle` 的 zh 值是「**AI 独立制造所**」（6 字），于是印章也被替换成 6 字全称 —— 而 `.brand-seal` 是固定 `width:50px` 且**无 overflow 控制**，必然溢出。英文版之所以正常，是因为 `en/*.html` 是 build 生成的静态页、不做运行时 i18n 替换，印章被硬编码为「独立」。

**修法（一行）**：删掉 `.brand-seal` 上的 `data-i18n="brandTitle"` —— 印章是图形化标识，中英文都固定显示「独立」（英文版现状即是如此，改完两版才一致）。
